# Collision research — the red team

Run this in full for every candidate that reaches the finalist round.
Instantiate a separate adversarial persona — **BRAND KILLER** — whose only
goal is elimination. A candidate is promoted only by surviving it.

## 1. Software and technology search

Search each of these literally:

```
"NAME" software              "NAME" technology
"NAME" technologies          "NAME" AI
"NAME" artificial intelligence
"NAME" SaaS                  "NAME" developer
"NAME" cloud                 "NAME" app
"NAME" startup               "NAME" digital
"NAME" consulting
```

In the company's home market, also search in the local language. For Brazil:

```
"NAME" sistemas              "NAME" tecnologia
"NAME" software Brasil       "NAME" tecnologia Brasil
```

## 2. Developer-ecosystem test — mandatory

**This is the test teams skip and regret.** Check whether the name already
means a tool developers use:

| Registry | What to check |
|---|---|
| GitHub | repositories and organisations |
| npm | package name |
| PyPI | package name |
| Maven Central | groupId / artifactId |
| Apache projects | top-level and incubating |
| CNCF landscape | graduated, incubating, sandbox |
| Docker Hub | official and popular images |

Ask: *does this name already mean an important developer tool?*

If yes, **discard**. Do not rationalise it with "there are other meanings".
A widely-known tool owns the name inside the audience you are selling to,
and no amount of brand investment reclaims it.

> Worked example: `MAVEN` is a legitimate English word meaning expert, and
> also one of the best-known build tools in the Java ecosystem. The second
> fact eliminates it. Full stop.

Second worked example: a name can look clean in web search and still die
here — a candidate whose `.dev` domain hosts an AI-coding-agent plugin and
whose GitHub org is active is disqualified even if no company by that name
exists.

## 3. Corporate search

- Google and Bing, exact match and phonetic neighbours
- LinkedIn companies
- Crunchbase
- Product Hunt
- GitHub Organizations
- Wellfound

Look for companies, startups, products, consultancies, software houses,
platforms and open-source projects.

Pay particular attention to **venture funds and consultancies** — they
occupy the same B2B mental space as a technology company even though they
sell something different.

## 4. App stores

Check the Apple App Store and Google Play for identical and phonetically
close names. A dormant app is a minor signal; an active one in an adjacent
category is a serious problem.

## 5. Cultural and linguistic screening

For every target language and major market:

- Does it mean something unintended?
- Is it vulgar or offensive in any regional variant? (Check Spanish
  regional slang specifically — a neutral word in one country can be
  obscene in another.)
- Does it collide with a politically loaded term, party or movement?
- Does it evoke a historically painful subject?
- Is it a common personal name that destroys searchability?

## 6. Wrong-category test

Ask what the name primarily reads as:

clothing · textile · pharmaceutical · bank · fintech · cryptocurrency ·
supplement · restaurant · cosmetic · industrial · law firm · agency

A strong association with the wrong category is a heavy penalty. A name
that sounds like a medication or a fabric will not carry a technology
company, no matter how well it scores structurally.

## 7. Evidence discipline

Record every finding with the real URL you retrieved. For each candidate
write one of:

- `CLEAR` — searched, nothing material found (list what you searched)
- `MINOR` — collisions exist, non-competing category, documented
- `MATERIAL` — collision in software / technology / adjacent B2B → eliminated
- `NOT VERIFIED` — could not complete the check

Never write `CLEAR` for a check you did not actually run.
